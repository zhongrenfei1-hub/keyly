# Keyly 前台改版：几份参考稿怎么用

用户 2026-11-14 连着贴了四份参考设计稿，要求照它们把 Keyly（卖 AI 账号等数字商品的自助售卖站）的前台改一遍。原文都在本目录，文件名以「参考-」开头。这份文件写的是「借什么、不借什么、换成什么」，实现和审查都以它为准。

## 总的规矩

- 只改买家看到的前台（`src/app/(shop)`、前台用的组件、`globals.css`）。后台、对账、下单和发货逻辑、数据库结构不动。
- 不用参考稿里的任何视频、图片、头像地址（都是别人的素材）。需要画面的地方用 CSS、SVG、canvas 自己画。
- **配色改成天蓝色**（用户 2026-11-14 说「配色改成天蓝色」，原来的紫色不再用）。全站的强调色和参考稿里的橙、红、黄绿渐变，一律换成天蓝色系：#0369A1 #0284C7 #0EA5E9 #38BDF8 #7DD3FC #BAE6FD #F0F9FF。
  - `globals.css` 里的 `--primary` 改成 #0EA5E9，悬停 #38BDF8，按下 #0284C7；压在它上面的字（`--primary-foreground`）用深海军蓝 #082F49，不要用白字（白字压在天蓝上对比度不够）。
  - 白底上的强调文字和链接用 #0369A1。
  - 代码里写死的紫色（#6D28D9、violet-*、传送带组件里的紫色调色板和 rgba(109,40,217,…)）全部找出来换掉，改完全仓库 grep 一遍确认没有残留。
  - 下面各节提到「紫色系」的地方都按天蓝色系理解。
- 不编造数字：不写销量、用时、好评率。示意内容要标明是示意。
- 文案用平实的中文，不照搬参考稿的英文。
- 不加深色模式开关。
- 遵守这版 Next（16.4，开着 Cache Components）的规矩，见 `AGENTS.md` 和 `README.md`：同步读库前先 `await io()`，读数据的组件放在 Suspense 里。
- 每次改完都要过：`npx tsc --noEmit`、`npx eslint src scripts`、`npm test`（27 条）、`npm run build`。

## 第一份：传送带（参考-Distill-传送带设计稿.md）→ 首页首屏

- 传送带上是店里真能买的商品卡；过了中间那条「付款」线，化成粒子，另一侧变成打了码的示意发货内容。
- 线上方的胶囊显示当前这张卡的进度百分比和「发货中 / 已发货」。
- 动效引擎、数值照稿子。组件在 `src/components/delivery-belt.tsx`。
- 字体照这份稿子，见下面「字体」。

## 第二份：三张指标卡（参考-Performance-三卡片设计稿.md）→ 换掉首页「为什么在这里买」

- 三张按 429×554 比例整体缩放的大卡，内部用一个单位变量排版，任何宽度下内部不重排。
- 中间是点阵（LED 圆点）拼的大数字，下面一句说明。每张卡有自己的 SVG 图形、颗粒、高光。卡片底色是紫色系里深浅不同的三种渐变。
- 三个数字只用站里真实成立的：
  1. 「3 步」：选商品、付款、拿卡密。
  2. 「0 次注册」：不用建账号。
  3. 「24 小时」：全天自助下单，付款后自动发货。
- 点阵字形要补上用得到的字符。卡片上不放「Learn More」按钮，除非有真实要去的地方（比如第一张跳到货架）。
- 入场动画照稿子（标题逐行揭开、卡片依次出现），只播一次，尊重 reduced motion。

## 第三份：玻璃质感组件（参考-玻璃质感组件设计稿.md）→ 全站前台的界面组件

- 卡片两种：白色实心卡（大圆角、柔和阴影）和半透明玻璃卡（背景模糊、细颗粒、顶部高光）。商品卡用实心卡；售罄、暂未开售的用玻璃卡。
- 分段切换（药丸底，选中项是白色小药丸加阴影）：用在顶部导航和首页的分类页签上。
- 白色小药丸标签（库存、付款方式）、圆形图标按钮、卡片底部的数字徽标。
- 过渡统一用 `cubic-bezier(0.22, 1, 0.36, 1)`，卡片悬停轻轻上浮。
- 玻璃后面要有东西才好看：页面底用自己写的柔和色块（紫色系加中性灰，很淡），不用视频。
- 手机上圆角和内边距按比例收小，不能出现横向滚动。

## 第四份：对话面板（参考-对话面板设计稿.md）→ 客服对话框

- 前台每一页右下角一个圆形的「客服」按钮，点开是一个对话框，样子照稿子第二屏的对话卡片：深色卡片、气泡、底部白色药丸输入条、发送按钮带一圈缓慢转动的光环（光环用紫色系）。
- 它不是真人在线聊天，也不接 AI，不能让买家以为有人在实时回复：
  - 打开先是一条自动问候，写明「这里是自动回复和留言，客服看到后按你留的邮箱回复」。
  - 几个常见问题做成可以点的小药丸，点了就用首页「常见问题」里现成的答案回一条气泡。
  - 买家输入的话当作留言：还要一个邮箱（必填）和订单号（选填），提交后走现成的售后工单（`submitTicket`），回一条「已收到」的气泡。限流、校验都用现成的。
- 可以用键盘操作，Esc 关闭，焦点管理要对；手机上对话框占满宽度。
- 入场动画照稿子的节奏，尊重 reduced motion。

## 第五份：页脚（参考-Kresna-页脚设计稿.md）→ 前台每一页的页脚

用户 2026-11-14 先贴了一份深色极光整屏的页脚稿（参考-Vantix-页脚设计稿.md，附言「页脚用这个」），随后又贴了这一份，问「或者用这个 你觉得呢」。定的是这一份：它是浅色页面上的两张圆角卡片，和站里现在的卡片是一路的；高度也合适（内页只有一张表单，挂不住一整屏的深色页脚）；它不靠别人的素材撑场面。Vantix 那份没采用，只借了一点意思：左边蓝卡里流动的光。原来的页脚是一张居中的玻璃卡，整个换掉。

**照稿子做的**

- 结构：页脚里一个两栏网格，左栏固定 350px，右栏占满，间距 16px，两张卡等高。网格最宽 1080px（稿子是 1150px，我们要和顶部导航、正文对齐）。网格下面是一个和它同宽的超大浅色字标水印，往上收 60px，垫在卡片后面。
- 左卡：最小高 340px、圆角 28px、内边距 32px、带蓝色调的投影。里面从上到下：标志（32px 的圆角小方块加站名）、两行标语（第二行淡一档）、底部一行「手写体小标签在左、一排深色圆角方块图标在右」。
- 右卡：圆角 28px、内边距 40px。上面是两列链接，列标题用手写体；右上角浮着一个斜放的立体方块，探出卡片上沿 36px，下面一句手写的话和一支手画的弯箭头；底部一行，左边是小字，右边是两行引导语加「输入框和深色按钮」那一行（宽 310px）。
- 尺寸、圆角、间距、字号、投影、悬停效果都照稿子的数字。两个断点也照稿子：860px 以下变成单栏；560px 以下右卡内边距 24px、两列链接间距 40px、底部那一行改成竖排、输入行占满宽度、方块缩到 72px 并往里收。
- 水印：SVG 文字，字的左右两端正好顶到容器两边。稿子靠脚本在字体加载完以后量字、改 viewBox；我们直接写一组预先量好的 viewBox，不用脚本（原因见下面补记）。
- 动效：稿子没有入场动画，只有悬停过渡（图标方块上浮变黑、按钮上浮、链接变色）。我们也不加入场动画。

**和稿子不一样的地方**

- 不用稿子里的视频（别人的素材，挂在别人的服务器上）。左卡的底用 CSS 自己画：深一档的天蓝色底上，几团慢慢漂移的亮色光。减弱动效（prefers-reduced-motion）时不动。标志和标语压着的地方底色要够深，白字的对比度不低于 4.5:1。
- 配色：稿子的蓝换成站里的天蓝色系。左卡在 #0369A1 到 #0284C7 一带，亮处可以到 #0EA5E9、#38BDF8；立体方块的渐变用 #38BDF8 → #0284C7 → #0369A1；链接悬停色 #0369A1；左卡和方块的投影用天蓝色调。深色小方块图标和深色按钮保持稿子的近黑（#0e1014、#111214），和站里的深色对话卡、传送带上的深色商品卡是一路的。
- 右卡的底：稿子是白页面上的浅灰卡。我们的页面底本身就是浅灰蓝，浅灰卡会和它糊在一起，所以右卡用白色实心卡（`card-solid` 那种），输入框那一行相应改成浅灰底。
- 字体：正文继续用站里的 Inter，不换成 DM Sans。手写体用 Caveat（经 `next/font/google` 打包进站里，不预加载）。Caveat 没有中文字形，而中文手写体要么各家设备上不一致，要么得再打包一套几兆的字体，所以**四处手写点缀用英文短语**。这是「文案用平实的中文」的例外：它们只是点缀，要去哪儿仍然由旁边的中文链接和无障碍名称说明。
- 标志：左卡里的标志和右卡的立体方块，都用站里现在的标志图形（钥匙图标），从 `src/components/brand.tsx` 取，不在页脚里另画一份。新标志还在设计，定稿以后只改 brand.tsx 一处。
- 文案和去处（不照搬稿子的英文，也不编不存在的东西）：
  - 左卡标语：「AI 账号与数字商品，」「付款即发货。」（就是 `SITE.tagline`，第二行淡一档）。
  - 左卡底部：稿子是「Stay in touch!」加四个社交图标。店还没有社交账号，不摆点不开的图标。换成手写的「Need help?」加三个深色方块图标，去的是买完以后最常用的三个地方：查订单（/orders）、兑换码取货（/redeem）、售后工单（/support）。每个图标都要有中文的无障碍名称和悬停提示。
  - 立体方块：稿子里是装饰。我们让它可以点，去首页的货架（`/#store`），旁边手写「Take a look?」加弯箭头；无障碍名称是「看全部商品」。
  - 两列链接：手写的列标题是「Shop」和「Orders」。「Shop」下面：全部商品（/#store）、兑换码取货（/redeem）、常见问题（/#faq，要给首页那一节加上 `id="faq"`）。「Orders」下面：查订单（/orders）、售后工单（/support）。
  - 右卡底部右边：稿子是订阅邮件。我们没有邮件订阅，换成查订单的快捷入口。两行字：「买过了？」「**输订单号，找回卡密。**」；下面一行是订单号输入框加深色按钮「查订单」。它是一个普通的 GET 表单，提交到 `/orders?no=…`；查订单页读到 `no` 就把订单号预先填好，买家再补上邮箱。查订单页只做这一处小改动（在浏览器里读网址参数，见下面补记）。页脚这个表单不开脚本也能跳过去。
  - 右卡底部左边：原来页脚的两条购买须知（「在本站付款的订单，付款成功后卡密直接显示在订单页；下单后库存为你保留 N 分钟，超时订单自动关闭。」「质保期限和退换条件以各商品页的说明为准。卡密有问题，请带订单号到售后页提交工单。」），一个字不改，`SITE.orderTtlMinutes` 照旧。再下面一行落款「© Keyly」，不写年份。小字用 `--muted-foreground`，不用稿子的 #9ca3af（对比度不够）。
- 水印：用 Inter 粗体写「Keyly」，颜色很淡（深蓝或黑，4% 到 6%）。
- 右下角固定着客服按钮（直径 60px，离右边和底边 16 到 20px）。它压在水印上没关系，但不能挡住右卡底部的输入框和按钮，手机宽度下尤其要查。
- 首页和内页（商品页、订单页、查订单、兑换、售后）用同一个页脚；后台不用。
- 内容不靠脚本才显示：脚本没跑，页脚里的字、链接、查订单那一行也都看得见、用得了。

**做的时候定下来的（2026-11-14 实现时补记，审查后改过三条：水印、订单号预填、光层裁切）**

文件：`src/components/site-footer.tsx`（服务端组件）、`site-footer.css`（类名都带 `ft-`）；查订单页的预填在 `src/app/(shop)/orders/prefill-no.tsx`；标志图形从 `brand.tsx` 新拆出来的 `LogoMark` 取。

- 流动光：左卡底色是 #0284C7 → #0369A1 的斜向渐变；上面两层比卡片大 30% 的径向渐变（#38BDF8、#0EA5E9、70% 的 #BAE6FD），各自来回漂，周期 23 秒和 31 秒；再盖一层不动的深色，颜色是 #0369A1 掺 35% 的 #082F49（算出来是 rgb(5, 85, 130)），分两团：左上角 300×160 的椭圆盖标志，左下角 460×320 的椭圆盖标语和手写标签（单栏时标语离底边远 40px，这团放大到 520×380）。在浏览器里量过，标志、标语、手写标签的四个角都落在深色完全不透明的范围里，所以光团漂到哪儿，字底下都是同一个颜色。光只从右上那一片透出来。
- 对比度（自己算的）：深色底上白字 8.0:1；标语第二行用 72% 的白（稿子是 65%，只有 4.4:1），5.0:1；手写的「Need help?」是 90% 的白，6.8:1。白卡上的灰字（手写的列标题、「Take a look?」、须知、「买过了？」）统一用 `--muted-foreground`，6.3:1；输入框的占位字压在 #f0f1f5 上 5.6:1；链接悬停色 5.9:1。焦点框：蓝卡上那三个图标用白色，里外各垫一圈近黑（单栏时图标底下是亮的光团，白框对它只有 2:1 出头），白卡上用 `--ring`（对白底 4.1:1，对输入行的灰底 3.6:1）。
- 水印：Inter 粗体 320 号字、字距 -0.03em，颜色是 5% 的 #082F49。预置的 viewBox 是 `21.04 -232.81 813.9 299.38`，是在浏览器里用 canvas 的 measureText 量出来的墨迹范围（不是 getBBox：getBBox 量的是字框，K 左边的留白会让字离左边差出二三十像素）。页面上不再跑量字的脚本：Inter 是打包在站里的，加载到了预置值就是准的；脚本只在 Inter 没加载到、落到系统字体时才有用，而它自己量错时（canvas 没认下字体设置）会把水印放大成一块碎片，不值得留。预置值只对「Keyly」这五个字母成立，站名改了要重量。
- 水印往上收：满宽时 60px，窄屏上按 5.5vw 少收一些（`max(-60px, -5.5vw)`）。照稿子固定收 60px 的话，手机上的字只有一百来像素高，会被卡片盖掉一半。
- 页脚上边留 48px（560px 以下 40px）：方块探出白卡上沿 36px，斜放以后还要多 8px，留够了它就压不到上面一节。
- 单栏（860px 以下）时方块只探出 20px：它上面 16px 就是蓝卡，蓝卡右下角是那排图标，照 36px 探出去离图标只剩 4px。560px 以下照稿子是 72px 的方块探出 28px，离图标 14px。方块会压住蓝卡底边十几像素，压不到图标。
- 360px 以下不显示「Take a look?」那一行：它会顶到第二列的标题「Orders」。方块还在，照样能点。
- 右卡底部那一行允许换行：右卡窄到须知和查订单并排不下时（视口大约 861 到 1095px，以及单栏的 561 到 760px），须知在上、查订单在下。须知最宽 420px。
- 查订单的输入框在手指点的设备上字号是 16px（稿子是 13.5px）：不到 16px，iOS 聚焦时会把整页放大。
- 方块是能点的，所以加了一个稿子没有的悬停：往上浮 3px。
- 订单号预填：一个很小的客户端组件，页面出来以后读网址里的 `no`（有几个取第一个，去掉首尾空白，最多留 40 个字符），订单号那一格是空的才填进去，填完把光标放到邮箱那一格。最初是在服务端读网址参数、放进 Suspense，`/orders` 因此变成「外壳静态、订单号那一格等请求进来再补」：从导航点过来时，空输入框先出现，等服务器回了再整个换掉，这中间打的字和光标会丢。现在 `/orders` 还是整页静态。不开脚本时不预填，页脚那个表单本身照样能跳过去。
- 左卡的两层光在 `.ft-glow` 里自己裁切，不靠卡片去裁：靠卡片裁的话，卡片里有了能滚动的内容，浏览器把里面的链接滚进视野时会把卡片里的内容一起滚歪。卡片上还留着 `overflow: hidden`，只是为了把直角的深色层裁成圆角。
- 查订单的输入框留了 96px 的 `scroll-margin-bottom`：聚焦滚进视野时停在右下角客服按钮的上面。滚到一半时客服按钮仍会压到它路过的东西（手机上包括「查订单」按钮的右端），滚到页面最底时不压。

## 字体

- 界面文字 Inter，大标题的衬线体 Newsreader，等宽 IBM Plex Mono。字体文件要打包进站里（`next/font`；构建机连不上 Google 时改用 npm 上的字体包），上线后不向 Google 发请求。
- 这三套没有中文：正文中文落到苹方等系统黑体；大标题的中文落到系统宋体类（Songti SC、Noto Serif SC、SimSun）。
